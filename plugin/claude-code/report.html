Salud de hooks

Hooks del arranque: chars que inyectan al contexto. Degradado = stderr, exitCode != 0 o salida que arranca con warning/error. Se compara con la sesion previa del proyecto (caida > 80% = aviso).

Cache-read — composicion del prefijo

__CLAUDIT_READ_PCT__%del total de tokens · lo que se reenvia cada turno

Cada barra es un componente del prefijo que se re-lee ENTERO en cada turno. % = componente / prefijo; tok = ese % aplicado al cache-read acumulado REAL de la sesion.

Setup fijo — desglose completo

__CLAUDIT_SETUP_TOTAL__tok/turno · piso fijo re-leido cada turno

Cada fila es un componente del piso fijo (la barra "setup fijo" de arriba, abierta). % = componente / setup fijo. Palanca = tok/turno editables que ahorras si lo recortas: *** ≥1000 · ** ≥300 · * <300 · — base del harness, no editable. Los CLAUDE.md se miden desde el adjunto instructions del transcript (lo que se cargo en la sesion); sin adjunto, del disco (estimado).

Cache-write — por inferencia

__CLAUDIT_WRITE_PCT__%del total de tokens

Una barra por inferencia (cada llamada a la API). Un turno = tu prompt hasta la respuesta: una barra azul seguida de sus naranjas. Altura = tokens nuevos escritos al cache en esa inferencia (el contenido que entro y se cacheo). El pico grande esta al arranque (se cachea el setup); despues cada inferencia escribe solo el delta nuevo (tu mensaje o el resultado de una tool). Aparecen picos EXTRA cuando el cache se re-crea: tras un /compact, tras un hueco de inactividad >__CLAUDIT_TTL__ (el cache expira, TTL) o al entrar contenido nuevo grande.

Arranque de turno — tu prompt (o la primera llamada tras una pausa ≥30 s)Inferencias hermanas — tool-calls encadenados del mismo turno (<30 s): re-leen el cache ya escrito y escriben solo el resultado de la tool⚠ Peligrosa — ese write (escribirlo + re-leerlo en cada inferencia siguiente) costo ≥1% del cupo de 5 h; sin el % cargado, la mas cara

Cargar el % de Account & Usage en Uso → Perfil de uso para ver cuanto tiempo de cupo resto cada write.

Loop agéntico

Cómo se encadena el trabajo dentro de cada turno. Cada inferencia re-lee todo el prefijo cacheado: tools en paralelo, menos lecturas encadenadas y sub-agentes para la exploración larga bajan el cache-read sin tocar el setup.

Prioridad de mejora

claudit muestra las mayores palancas por ahorro potencial por turno. Recortar, reordenar o no tocar nada es una decisión a criterio del usuario — esto es visibilidad, no una receta.

    __CLAUDIT_TIPS__
Metodologia

El TOTAL de cache-read, cache-write, input y output de la sesion es el dato real que reporta la API de Anthropic (usage de cada inferencia del transcript) — no es una estimacion. El REPARTO interno del cache-read entre setup fijo, prompts, tool results y respuestas se estima por proporcion de caracteres del contenido del transcript, calibrado contra el prefijo real de la ultima inferencia. El total nunca se estima; el desglose interno si, y se declara como tal.

Contexto actual — como /context

Contexto de la ULTIMA inferencia por categoria, como el panel /context de Claude Code. Las categorias fijas salen del desglose del setup; Messages es el resto del contexto usado. Autocompact buffer = reserva de 33k antes del auto-compact. La ventana se estima por modelo (fijarla con --ventana N).

__CLAUDIT_CURVA__

Perfil de uso — cuanto aguanta el cupo de 5 h

El riesgo real no es el costo: es quedarse sin cupo antes del reset y no poder usar la sesion hasta que vuelva. El contexto que crece es la causa (cada inferencia re-lee el prefijo entero) y el bloqueo es la consecuencia. El % de la cuenta no se lee por ninguna via soportada: se carga a mano desde Account & Usage. Con ese dato el reporte escala el consumo local (ultimos 30 min) a % de cupo y proyecta cuando se agota. Supone que todo el uso del bloque es de esta maquina.

__CLAUDIT_PERFIL__

Cómo se usó la sesión — turno a turno

Los graficos del dashboard de Claude, pero de ESTA sesion y con el eje en turnos (prompt humano → respuesta final) en vez de dias. Autonomia = tool calls por turno separadas en tools nativas, conectores MCP y sub-agentes; actividad = inferencias y tool calls por turno; profundidad = cuantos turnos llegaron a 5+ y 20+ tools; adherencia = % de turnos que usaron cada familia de tools. Misma numeracion de turnos que Loop agentico.

__CLAUDIT_SESION_USO__

Cupo — consumo local

Suma de TODAS las sesiones locales (todos los proyectos, sub-agentes incluidos) en la ventana de 5 h. Procedencia: observed = leido del transcript · calculated = suma de tokens reales · estimated = precio por modelo · unknown = sin via soportada (el cupo de la cuenta no se consulta: sin endpoints privados ni credenciales).

__CLAUDIT_CUPO__

Uso por mes

Metricas estilo dashboard de Claude, pero de un solo usuario y calculadas del transcript local (sub-agentes incluidos). El selector de ambito cambia entre TODOS los proyectos y solo este proyecto (esta sesion incluida). Lineas aceptadas = lineas agregadas por Edit/Write aplicados; accept rate = ediciones aplicadas / (aplicadas + rechazadas); acciones por prompt = tool calls / prompts humanos; adherencia = dias activos / dias transcurridos del mes. Costo estimado por precio de modelo.

__CLAUDIT_USO__

Skills — de donde viene cada una

Todas las skills que carga el skill_listing de esta sesion, con su proveedor. Prefijo anthropic-skills: = Anthropic via claude.ai; prefijo plugin: = ese plugin; carpeta ~/.claude/skills = el author de su SKILL.md, o personales globales si no lo declara (el nombre se cambia con etiqueta_personales en ~/.claude/claudit.json); .claude/skills del repo = proyecto; el resto viene incluido con Claude Code (Anthropic). "Vista desde" es la primera vez que aparece en un transcript local: un piso, no la fecha de creacion, porque Claude Code borra los transcripts viejos.
