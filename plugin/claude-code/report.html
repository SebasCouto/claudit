Contexto de la ULTIMA inferencia por categoria, como el panel /context de Claude Code. Las categorias fijas salen del desglose del setup; Messages es el resto del contexto usado. Autocompact buffer = reserva de 33k antes del auto-compact. La ventana se estima por modelo (fijarla con --ventana N).

__CLAUDIT_READ_PCT__%del total de tokens · lo que se reenvia cada turno

Cada barra es un componente del prefijo que se re-lee ENTERO en cada turno. % = componente / prefijo; tok = ese % aplicado al cache-read acumulado REAL de la sesion.

Setup fijo — desglose completo

__CLAUDIT_SETUP_TOTAL__tok/turno · piso fijo re-leido cada turno

Cada fila es un componente del piso fijo (la barra "setup fijo" de arriba, abierta). % = componente / setup fijo. Palanca = tok/turno editables que ahorras si lo recortas: *** ≥1000 · ** ≥300 · * <300 · — base del harness, no editable. Los CLAUDE.md se miden desde el adjunto instructions del transcript (lo que se cargo en la sesion); sin adjunto, del disco (estimado).

Cache-write — por inferencia

__CLAUDIT_WRITE_PCT__%del total de tokens

Una barra por turno. Altura = tokens nuevos escritos al cache ese turno (el contenido que entro y se cacheo). El pico grande esta al arranque (se cachea el setup); despues se escribe algo cada turno segun cuanto contenido nuevo entro. Aparecen picos EXTRA cuando el cache se re-crea: tras un /compact, tras un hueco de inactividad >__CLAUDIT_TTL__ (el cache expira, TTL) o al entrar contenido nuevo grande. Color: azul = primera inferencia del turno; naranja = inferencias hermanas (tool-calls encadenados del mismo turno, que comparten el cache ya re-escrito — no son un write nuevo).

Prioridad de mejora

claudit muestra las mayores palancas por ahorro potencial por turno. Recortar, reordenar o no tocar nada es una decisión a criterio del usuario — esto es visibilidad, no una receta.

    __CLAUDIT_TIPS__
Metodologia

El TOTAL de cache-read, cache-write, input y output de la sesion es el dato real que reporta la API de Anthropic (usage de cada inferencia del transcript) — no es una estimacion. El REPARTO interno del cache-read entre setup fijo, prompts, tool results y respuestas se estima por proporcion de caracteres del contenido del transcript, calibrado contra el prefijo real de la ultima inferencia. El total nunca se estima; el desglose interno si, y se declara como tal.
